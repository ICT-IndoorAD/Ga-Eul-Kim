# ICT Project Air Dashboard

아두이노와 실내 공기질 센서로 직접 수집한 데이터를 분석하고 시각화하는 ICT PBL 웹 대시보드입니다. 온도, 습도, CO₂, VOC, PM2.5의 현재 상태와 시간에 따른 변화를 확인하고, 외부 환경과 비교해 환기 여부를 판단할 수 있도록 구성했습니다.

서울·인천 공공데이터는 분석에 사용하지 않습니다. 대시보드의 실내 분석 결과는 프로젝트에서 직접 수집한 `air_log.csv`를 기반으로 하며, 외부 환경은 Open-Meteo의 현재 날씨와 PM2.5를 실내 측정값과 비교할 때만 사용합니다.

## 프로젝트 목적

- 아두이노 센서 데이터를 웹에서 쉽게 확인
- 실내 공기질의 현재 상태와 시간 패턴 파악
- 실내·외부 환경 비교를 통한 환기 의사결정 지원
- 센서 고정값과 비정상 급등값이 분석을 왜곡하지 않도록 데이터 품질 반영
- 새로운 CSV를 코드 수정 없이 브라우저에서 다시 분석

## 사용 센서와 측정 항목

| CSV 열 | 측정 항목 | 단위 | 활용 |
| --- | --- | --- | --- |
| `timestamp` | 측정 시각 | 날짜·시간 | 시계열 정렬과 수집 세션 구분 |
| `dht_temp_C` | DHT11 온도 | ℃ | 현재 상태, 쾌적 범위, 추세 분석 |
| `dht_humi_pct` | DHT11 습도 | % | 현재 상태, 쾌적 범위, 추세 분석 |
| `am_temp_C` | AM 센서 온도 | ℃ | 센서값 비교와 품질 확인 |
| `am_humi_pct` | AM 센서 습도 | % | 센서값 비교와 품질 확인 |
| `co2_ppm` | 이산화탄소 | ppm | 공기 정체 및 환기 필요성 판단 |
| `voc_level` | 휘발성유기화합물 | 단계 | 실내 오염 상태 참고 |
| `pm25_ugm3` | 초미세먼지 PM2.5 | µg/m³ | 농도 상태, 고농도 이벤트, 실내외 비교 |

## 현재 데이터 요약

- 원본 데이터: 124,251행
- 분석 사용 데이터: 123,380행
- 제외 데이터: 871행
- 실제 관측시간: 약 36.88시간
- 수집 세션: 2개
- 측정 간격 중앙값: 1초
- PM2.5 최고값: 65 µg/m³
- PM2.5 35 µg/m³ 초과 비율: 약 0.07%
- 온도 20~26℃, 습도 40~60% 쾌적구간 체류율: 약 66.1%

## 데이터 정제 기준

센서 전원 연결 직후의 불안정한 값과 짧은 시험 측정이 그래프 및 최신값을 왜곡하지 않도록 다음 기준을 적용했습니다.

1. 각 수집 세션의 초기 15분은 센서 예열 구간으로 보고 제외합니다.
2. 전체 길이가 15분보다 짧은 수집 세션은 분석에서 제외합니다.
3. 시계열 그래프는 1분 단위 평균값으로 표시합니다.
4. 데이터가 5분 이상 끊긴 구간은 그래프 선을 연결하지 않습니다.
5. 원본 `data/air_log.csv`는 수정하지 않고, 정제 결과는 `data/dashboard_data.json`에 별도로 저장합니다.

## 대시보드 구성

### 1. 개요

- DHT 온도, DHT 습도, CO₂, PM2.5, VOC의 마지막 유효 측정값
- 항목별 좋음·보통·주의 상태
- 실내 측정값과 외부 PM2.5를 조합한 환기 행동 제안
- 전체 CO₂ 추세와 기준선
- 데이터 품질 기반 예측 준비도
- 실제 관측시간, 쾌적구간 체류율, 수집 세션 수

### 2. 실내외 비교

- 실내와 외부의 온도, 습도, PM2.5 비교
- 외부 풍속 확인
- 도시 검색 및 서울 기본값 제공
- 외부 PM2.5가 높은 경우 창문 환기 보류 안내
- 실내 오염도가 외부보다 높은 경우 환기 권장

외부 값은 Open-Meteo API에서 불러옵니다. API 호출에 실패하거나 인터넷에 연결되지 않은 경우에도 실내 데이터 화면은 정상적으로 유지됩니다.

### 3. 추세 분석

- PM2.5 1분 평균과 1분 최대값
- DHT11 온도와 습도의 시간 변화
- 전체, 최근 관측 24시간, 최근 관측 6시간 범위 선택
- PM2.5 및 CO₂ 참고 기준선 표시

### 4. 예측 실험

- 온도, 습도, PM2.5의 5분·10분·30분 후 단기 예측
- 현재값 유지 모델과 최근 30분 선형 추세 모델 자동 비교
- 과거 구간 백테스트를 이용한 최적 모델 선택
- 항목별 평균 절대오차, 검증 횟수, 신뢰도 표시
- CO₂는 장시간 고정값 문제로 예측에서 제외

### 5. 이벤트

- PM2.5와 CO₂의 최고값 요약
- PM2.5 주의구간 비율
- 기준을 초과한 구간의 시작·종료 시각, 지속시간, 최고값

## 기준값 해석

대시보드의 기준선은 실험 데이터를 이해하기 위한 참고값입니다.

- CO₂: 800 ppm부터 보통, 1,000 ppm부터 환기 필요 상태, 1,500 ppm 이상을 매우 나쁨으로 표시합니다.
- PM2.5: 15 µg/m³ 이하를 좋음, 35 µg/m³ 이하를 보통, 35 µg/m³ 초과를 나쁨으로 표시합니다.
- 온도·습도 쾌적 범위: 온도 20~26℃, 습도 40~60%를 사용합니다.

PM2.5의 35 µg/m³는 에어코리아 24시간 평균 등급의 `보통` 상한을 참고한 경보선입니다. 실내 순간 측정에 대한 법적 판정 기준은 아닙니다.

## 데이터 품질과 예측 한계

현재 데이터 124,251행 중 124,214행의 CO₂가 813 ppm으로 고정되어 있습니다. AM 센서에서도 온도 0℃, 습도 99%가 장시간 유지되는 패턴이 확인됩니다. 이러한 값은 실제 환경 변화보다 센서 초기화, 통신 또는 측정 오류일 가능성이 높습니다.

따라서 현재 버전은 신뢰하기 어려운 예측값을 억지로 제공하지 않고 다음과 같이 처리합니다.

- CO₂ 고정값 비율을 예측 준비도에 반영
- 데이터 품질이 부족하면 CO₂ 예측 자동 중지
- 정상적인 CO₂ 변동 데이터가 충분히 쌓이기 전에는 현재 상태와 추세 중심으로 활용

향후 정확한 예측을 위해서는 정상적으로 변하는 CO₂ 데이터, 연속 측정 기간, 공간 정보, 인원수, 창문 상태, 환기장치 작동 여부 등의 실험 조건이 추가로 필요합니다.

## 실행 방법

이 프로젝트는 별도 패키지 설치가 필요 없는 정적 웹 프로젝트입니다. 브라우저에서 HTML 파일을 직접 여는 대신 로컬 서버로 실행해야 JSON 데이터를 정상적으로 불러올 수 있습니다.

### VS Code에서 실행

1. VS Code에서 `ICT_Project_Air_Dashborad` 폴더를 엽니다.
2. 상단 메뉴에서 **터미널 → 새 터미널**을 선택합니다.
3. 다음 명령을 실행합니다.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

8000번 포트가 이미 사용 중이면 다른 포트로 실행할 수 있습니다.

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

4. 브라우저에서 다음 주소로 접속합니다.

```text
http://127.0.0.1:8000
```

서버를 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

## 새로운 CSV 사용 방법

대시보드 오른쪽 위의 **CSV 불러오기**를 선택하고 동일한 열 구조의 CSV 파일을 업로드합니다. 파일은 서버로 전송되지 않으며 현재 브라우저에서만 분석됩니다.

CSV 헤더는 다음 형식을 사용해야 합니다.

```csv
timestamp,dht_temp_C,dht_humi_pct,am_temp_C,am_humi_pct,co2_ppm,voc_level,pm25_ugm3
```

## GitHub Pages 배포

1. 프로젝트 폴더의 파일을 GitHub 저장소에 올립니다.
2. 저장소의 **Settings → Pages**로 이동합니다.
3. **Deploy from a branch**를 선택합니다.
4. `main` 브랜치와 `/ (root)`를 지정합니다.
5. 저장 후 생성된 GitHub Pages 주소로 접속합니다.
